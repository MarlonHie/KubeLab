## Container beginnen mit Linux

Ein Container ist ein Prozess auf dem Host. Er nutzt denselben Kernel wie andere Prozesse, bekommt aber eine eingeschränkte Sicht auf das System und ein eigenes Dateisystem. Eine virtuelle Maschine startet dagegen einen eigenen Kernel.

### Zwei Mechanismen, zwei Aufgaben

**Namespaces** isolieren die Sicht auf Ressourcen: Der PID-Namespace zeigt eigene Prozessnummern, der Network-Namespace eigene Netzwerkschnittstellen. Ein Mount-Namespace ermöglicht eine eigene Sicht auf eingebundene Dateisysteme.

**cgroups** fassen Prozesse zusammen und begrenzen beispielsweise CPU-Zeit und Arbeitsspeicher. Isolation und Ressourcenbegrenzung sind unterschiedliche Aufgaben; Container verwenden beides.

### Im eigenen Terminal erkunden

Die folgenden lesenden Befehle kannst du in einer Linux-VM ausführen. Das Browserterminal führt sie nicht aus.

```bash
ps -eo pid,comm --sort=pid | head
lsns
cat /proc/self/cgroup
systemctl status containerd --no-pager
```

Falls containerd noch nicht installiert ist, meldet systemd eine unbekannte Unit. Das ist hier kein Fehler: Du installierst die Runtime später im Build Lab.

### Deine Aufgabe

Vergleiche zwei Prozesse mit `lsns`. Welche Namespaces teilen sie? Erkläre dann in eigenen Worten, warum ein Container keine vollständige virtuelle Maschine ist.

### Wenn etwas nicht klappt

Unter Windows brauchst du für diese Befehle Linux, zum Beispiel in einer VM oder WSL2. Einige Informationen in `lsns` sind nur mit erhöhten Rechten sichtbar. Verändere für diese Aufgabe keine Systemkonfiguration.
